# PAYATHON 2026 演示脚本（10 分钟）

- 赛道：Vibe Pay（主赛道）
- 目标：在 10 分钟内把「产品完整度 / 支付集成 / 商业化 / 影响力」四个评分维度各演到一次
- 相关文档：`p1-payment-admin-design.md`、`payment-acceptance-report.md`

## 评分映射

| 时间 | 演示内容 | 对应评分 |
| --- | --- | --- |
| 0:00–0:40 | 一句话产品 + 谁为什么付费 | 商业化 |
| 0:40–3:00 | 建档 → 周计划 → 记录一组 | 产品完整度 30% |
| 3:00–5:00 | 真实/沙箱支付 → 回跳 → Pro 到账 | 支付集成 25% + 商业化 25% |

| 9:00–10:00 | 审计列表、付费用户数、引导评论 | 影响力 20% |

## 演示前置检查（提前 30 分钟）

1. **部署稳定**：前端线上地址可访问；后端 `FITPLAN_PUBLIC_BASE` 是评审期可用的固定公网地址；`/api/health` 回 `db: up`。
2. **收款资格**：aipay 后台已开通「网页应用收款」（或移动应用收款）；接入 AI 付的支付宝账号与报名账号一致。
3. **支付环境**：真实小额还是沙箱已定；网关地址、价格（`FITPLAN_PRO_PRICE_YUAN`）、天数确认。
4. **管理端**：`FITPLAN_ADMIN_LOGIN/PASSWORD` 配好；`#/admin` 能登录；不要提前泄露给观众以外的人。
5. **数据准备**：
   - 一个免费账号（用来现场付款；「数据与备份」里云端上传/拉回应显示为锁定）
   - 一个 Pro 账号（用于展示云端同步/跨设备备份可用）
   - 一笔「支付宝已扣款、本地订单仍为 created」的订单（用于演示通知丢失）
   - 一笔已支付订单（用于演示退款）
6. **演示顺序**：先查单救单，再退款；避免退款把待演示用户的权益提前扣掉。
7. **录屏兜底**：提前录一份完整流程，现场网络异常时切换播放。

## 时间轴与台词

### 0:00–0:40 开场

> 「练」是一个移动端优先的健身计划 PWA：把目标翻成周框架，每天给一张按顺序做的清单，逐组记重量，下一次按你自己的力量往上推。
>
> 它免费能用；付费的是 **Pro 会员**：跨设备云端同步、长期备份，以及 12 周趋势和每周报告 —— 训练记录丢一次就找不回来，这是愿意持续付钱的点。

### 0:40–3:00 用户主路径（产品完整度）

1. 打开线上地址 → 进入应用 → 完成或展示已完成的档案（身体数据、目标、器械）。
2. 展示本周框架：哪几天练、每天哪个部位。
3. 进入今天清单，记录一组重量/次数，展示重量推算与历史。
4. 可选 30 秒：点动作卡片的「动作检查」，展示摄像头骨架和调整建议（现场没有摄像头就跳过，改讲本机处理、不上传）。
5. 可选 20 秒：记录页 →「趋势与周报」。Pro 账号展示 12 周容量/力量/体重曲线和最近 7 天周报；换成免费账号只显示近 7 天，并出现升级入口。
6. 一句话：**免费就能把训练跑完，数据全在本机。**

### 3:00–5:00 支付（支付集成 + 商业化）

1. 设置 → 账号 → 升级 Pro（¥8 / 30 天）。
2. 跳支付宝收银台 → 付款（真实小额或沙箱）。
3. 回到 App：展示「这一单到账了」和 Pro 到期日。
4. 说清链路：下单 → 收银台 → 异步通知验签 → 金额按分比对 → 幂等发货 → 权益到账；**发货只认支付宝的事实，不认前端回传**。

### 5:00–7:00 通知丢失救单（支付集成，最抓人的一段）

1. 说明：公网环境下异步通知可能丢失，订单会停在「待支付」，但用户其实已经付了钱。
2. 打开 `#/admin` → 订单搜索这笔单 → 订单详情。
3. 点「主动查单」→ 支付宝返回 `TRADE_SUCCESS` 且金额一致 → 本地发货、Pro 到账。
4. 展开审计：谁、何时、为什么补发。
5. 台词：

> 这条链路不依赖通知一定送达。查单和通知共用同一个幂等入口，重复查、重复通知都不会重复加天数。

### 7:00–9:00 退款（支付集成，细则明确考核）

1. 管理页选一笔已支付订单 → 「全额退款」→ 填原因（如「七天无理由」）→ 确认。
2. 展示：支付宝退款成功、订单变「已退款」、用户权益按本单天数收回；用户端再打开设置页显示「已退款到支付宝，Pro 权益已收回」。
3. 台词：

> 退款是整单全额，`out_request_no` 用订单号做幂等；先确认支付宝退钱，再动本地权益。结果未知时用退款查询对账。

### 9:00–10:00 收尾

1. 审计页：查单、退款、补发全部留痕。
2. 商业化：展示真实付费用户数（主办方统计口径）与定价逻辑。
3. 影响力：请评委在作品详情页点赞/评论；说明社区反馈会进入后续迭代。

## 备用方案

| 现场问题 | 处理 |
| --- | --- |
| 网络/支付宝不可用 | 切录屏；口头讲清验签、金额比对、幂等、退款回收 |
| 支付回调延迟 | 等待 3–5 秒；前端每 2 秒查一次，最多 3 次；仍无则讲「管理页手动查单」 |
| 管理页登录失败 | 检查 `FITPLAN_ADMIN_*` 是否配了、密码是否 ≥12 位、IP 白名单 |
| 退款失败 | 展示错误文案；用「退款查询」确认状态，不现场改库 |

## 不能做的事

- 不刷单、不伪造付费用户（细则明确剔除并取消资格）。
- 不展示或读取用户的训练、饮食、身体数据（管理端本身也没有这个能力）。
- 不在演示中暴露管理员密码、支付宝私钥、数据库密码。
