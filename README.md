# 练

移动端优先的健身计划 PWA：把「想练成什么样」翻成一份周框架，每天生成一张按顺序往下做的清单，逐组记重量和次数，重量按你自己的记录往上推。

在线地址：<https://minute-fitplan-9u7zherxrt7.qoder.zone/>

## 里面有什么

- **建档两问**：身体数据、想练成什么样，都能跳过，也可以一句「先不设目标，自由练」。训练日不问：默认周一到周四，练哪天自己在那个页面上挪。
- **新手不用先懂分化**：没系统练过的人直接拿到一套四练三分化（周一 胸+三头 / 周二 背+二头 / 周三 腿+臀 / 周四 肩+手臂），一次四个动作、每个 3 组 10–15 次，前两周重量按周计划不动，第三周起做满次数才加。
- **周框架自己点**：哪天练、那天练哪个部位由你决定，组数 / 次数 / 重量由本机规则按你的器械条件、伤病记录和逐组历史算，排课不请求任何模型。动作记过一次之后，重量就只按你自己的记录往上推，不再用估算值。
- **动作库 109 个**：按部位分区，每个动作有本机画的 SVG 动作示意、发力顺序、常见错误和同肌群替代动作。44 个动作预置了示范视频链接，指向 [谭成义](https://space.bilibili.com/521903482) 本人的 B 站与抖音页面 —— 只放链接，不复制、不内嵌。
- **逐组记录**：记每一组的重量和次数，可选 RPE；能加一组、删一组、给某个动作挂递减组（按档记重量和组数）、拖卡片改顺序，不想练的那一行直接从天里拿掉。
- **摄像头动作检查**：动作卡片上的「动作检查」会用 MediaPipe Pose 在本机提关键点，实时画骨架，结束后给次数、速度、髋/膝/躯干角度和具体调整量（深蹲深度、躯干前倾、左右不对称、节奏等）。画面只在本机处理、不上传、不保存；单目摄像头是估算，界面会写明「参考，不是教练或医学判断」。需要 HTTPS 或 localhost 才能拿到摄像头。
- **主屏 App 体验**：安装到主屏后从图标启动，没有地址栏；动作检查全屏打开摄像头，运行时屏幕常亮，Android 返回键先关相机而不是退出应用。设置 → 数据与备份里有安装入口。
- **身体数据打卡**（在「记录」里）：每天称一次体重、隔几周量一次腰围，记下来就有折线和周变化。判断按最近两个 7 天平均相减，不按某一天说话；走势对着你目标的节奏（减脂一周 0.5–1%，超过 1% 就提醒你别再砍热量），还能一键把最新一次称重更新进档案，热量参考跟着走。
- **饮食**：按 Mifflin-St Jeor 估基础代谢再乘活动系数给一日热量参考，另有蛋白 / 碳水 / 脂肪 / 糖 / 钠五项区间、65 条常见食物营养表、按档案算出的三份主食方案。另加膳食纤维、钙、铁（按性别）、钾、维生素 D、B12、镁 7 项微量元素参考，65 种食物里 43 种有每份粗值，没覆盖的按未计处理。
- **离线可用**：可以添加到主屏幕，断网能看档案、翻清单、记组数。

## 数据放在哪

默认全部留在这台设备的浏览器 `localStorage`（键名 `fitplan.v1`）：档案、周框架、训练记录、饮食记录、打卡、体重腰围、示范视频链接。可以在「设置 → 数据与备份」导出成一份 JSON 自己留着，也能导回来。清空浏览器数据就没了，所以导出是唯一的保底。

登录是可选的，两种登录方式都支持：**账号密码**（本机起了后端就能注册，不需要任何第三方应用）和**支付宝授权**（要在开放平台建应用）。云端那张 `users` 表只有账号名或支付宝 uid 的后四位、订阅状态和会话；训练和饮食的内容不点「传到云端」就一个字节都不上来，点了也是按账号存一份整档，随时能删，注销账号连着一起删。密码只存 PBKDF2-HMAC-SHA256 的散列，明文不落库，忘了找不回来。

大模型 Key 由使用者自己填，明文存在本机浏览器里，不上传 —— 共用设备上不要填。

## 后端（可选）

前端默认请求同源的 `/api`，不跑后端也能用；没连上时登录和云端备份那几处会直接说连不上，本机记录不受影响。

```bash
# 1. 建库
mysql -u root -p -e "CREATE DATABASE fitplan DEFAULT CHARSET utf8mb4"

# 2. 配凭据
cp server/.env.example server/.env   # 填 MySQL 密码；server/.env 已在 .gitignore 里

# 3. 起服务（默认 8787，和 vite.config.js 的代理目标一致）
npm run api:build
npm run api
```

支付宝授权登录和收款要在开放平台建应用，把 `ALIPAY_APP_ID`、应用私钥、支付宝公钥填进环境变量，`FITPLAN_PUBLIC_BASE` 必须是支付宝服务器打得到的公网地址，否则收不到异步通知。没配支付宝也不影响登录：账号密码那一套是独立的。

`/api/health` 默认只回 `db` / `alipay` / `pay` 三个状态，缺哪些环境变量、CORS 白名单里有谁都不写在回应里 —— 挂着公网时这是给陌生人看的。自己排查时把 `FITPLAN_HEALTH_DETAIL=1` 打开再访问就有全部细节。

## 云端备份的覆盖保护

「传到云端」是整份覆盖，所以每次上传会带上本机上一次看到的云端时间戳（存在 `localStorage` 的 `fitplan.cloud`）。后端发现库里那份比这个时间新，就回 409 不写，界面上会问一句「先拉回来看看，还是确定用本机这份覆盖」—— 另一台设备刚传过东西的时候，这一句就是防你把别人的记录盖掉。

云端同步（上传 / 拉回）是 **Pro 权益**：免费版或订阅过期后，`POST /api/data/sync` 和 `GET /api/data` 回 402，设置页会把这两个按钮锁上并给升级入口。删除云端那份（`DELETE /api/data`）不设门槛，订阅过期也能随时清掉。

## 趋势与周报

记录页里的「趋势与周报」进入 `#/trends`，数据全部在本机现算，不上传。

- 免费版：最近 7 天的训练天数、容量、饮食记录天数和体重变化，可以给今天记体重/腰围。
- Pro：近 12 周的每周容量、主项最佳估算 1RM、体重走势，以及最近 4 个 7 天窗口的周报（训练、力量、饮食、体重和提醒）。
- 周报只描述记录里的趋势，不做诊断；体重/腰围打卡存进 `measureLogs`，跟着整份导出和云端备份走。

## 账号密码登录

后端起来就有这两个接口，不需要任何第三方应用：

```bash
curl -X POST localhost:8787/api/auth/register -H 'Content-Type: application/json' \
  -d '{"loginName":"lin_01","password":"xxxxxxxx"}'      # 换成 /api/auth/login 就是登录
```

回 `{token, kind, handle, plan}`，前端把 token 存进 `localStorage` 之后的会话接口都靠它。约束：账号名 3–32 个字符（存的时候统一小写），密码 8–64 位且不能全是数字；同一个「账号名 + 来源地址」连错 8 次冷十五分钟。库里存的是 `PBKDF2-HMAC-SHA256`（12 万次迭代、16 字节随机盐）的散列，不是明文也不是可逆加密。

## 支付、查单与退款

下单走支付宝 `page.pay` / `wap.pay`，发货只认两样：异步通知的验签结果，或主动查单 `alipay.trade.query` 的返回。两条路径共用同一个幂等入口（`orders.status` 从 `created` 到 `paid` 只有一次机会），金额一律按分和订单表里的 `amount_cent` 比，通知里写多少都不作数。

- **通知丢失**：用户从收银台回来时前端会问一次，后端最多每 10 秒向支付宝查一次该订单（`POST /api/pay/order/refresh`）；管理员也可以在管理页手动「主动查单」。
- **退款**：管理员在管理页做全额退款（`alipay.trade.refund`，`out_request_no` 用订单号做幂等），确认退钱后才收回**本单购买的天数**；扣到当天就降为免费版。退款结果未知时用「退款查询」（`alipay.trade.fastpay.refund.query`）对账。
- **交易关闭**：查单返回 `TRADE_CLOSED` 时本地订单置 `closed`，不动权益。

`orders` 表保留支付事实（`status`），退款单独记录在 `refund_status / refund_cent / refunded_at`，方便对账和审计。

## 管理后台（可选）

管理端是一个独立整屏页面，地址 `#/admin`，不在用户底部导航里，也没有任何入口链接。不配置管理员时，所有 `/api/admin/**` 都回 404。

```bash
# server/.env（示例见 server/.env.example）
FITPLAN_ADMIN_LOGIN=ops_admin
FITPLAN_ADMIN_PASSWORD=<至少 12 位的随机串>
FITPLAN_ADMIN_SESSION_HOURS=12          # 可选，默认 12
FITPLAN_ADMIN_IPS=                      # 可选，逗号分隔的 IP 白名单
```

账号只在后端启动时创建一次，已存在不会覆盖密码；没有注册接口。能做四类事：

| 能力 | 说明 |
| --- | --- |
| 订单 | 按状态/订单号/交易号/账号/uid 尾号搜索；详情含金额、天数、交易号、`buyer_id`、时间线 |
| 查单发货 | 通知丢失时手动查支付宝并把订单推到 `paid`，与通知共用幂等发货；发货成功写审计 |
| 退款 / 退款查询 | 全额退款并收回本单天数；结果未知时用退款查询补账 |
| 用户与审计 | 只返回账号元数据（账号名、uid 尾号、权益、到期、已付订单数）；手工补发/撤销必须填原因；所有变更进 `admin_audit` |

安全约定：管理员独立于用户表（`admin_users` / `admin_sessions`），密码同样走 PBKDF2；未认证或无此路由统一 404；登录连错 8 次冷 15 分钟；审计记录保留管理员登录名快照，用户删除后仍可读。**管理端没有任何读取训练、饮食、身体数据的能力。**

## 让线上站点也能登录（内网穿透）

线上那份站点是纯静态的，同源没有 `/api`。要把本机后端挂出去，先起隧道：

```bash
npm run api                                   # 本机 8787
npm run tunnel                                # 打印一个 https://xxxx.trycloudflare.com 的公网地址
```

然后在「设置 → 数据与备份 → 后端地址」里填上 `https://xxxx.trycloudflare.com/api` 保存，全站立刻走这个地址；点「用同源」就退回本机没后端的状态。支付宝的异步通知也要打这个地址，所以收款时还得把它写进 `FITPLAN_PUBLIC_BASE` 再重启后端。

隧道每次启动换一个域名，而且本机服务一关线上就断 —— 这条链路适合联调和演示，不适合长期给陌生用户用。
